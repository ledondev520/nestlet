# Nestlet 设计系统契约

2026-10-07 · 适用：会话首页、客户／案件目录、事实核对、文档阅读与编辑、账户及设置。状态：**实施与验收契约，不是 UI 已通过报告**。

## 1. 决策权与范围

- **Kimi 主导审美、UI/UX 和布局，确定令牌数值及双端参考画面；Root 负责 shadcn/ui 工程迁移与业务接线；实际浏览器验收单独留证。** 本次分工取代旧文档中与此冲突的前端实施分工，不许可多人同时修改同一文件。
- 当前产品范围以 [current-delivery-contract](current-delivery-contract.md) 为准；[旧旅程验收](nestlet-ux-journey-guidance.md) 中仍适用的可访问性、恢复、隔离要求继续沿用。旧的“仅一次上传／不含客户目录”不能限制新会话流程。
- 采用真实 shadcn/ui 组件来源、集中封装和语义令牌，不以相似 CSS 冒充迁移。记录所选 primitive 实现、组件来源／版本及本地改动；不要混用不同实现的 API。保留业务状态、API、权限与数据约束。shadcn/ui 是可定制的组件基础，**使用它不会自动获得 WCAG 合规**。[官方介绍](https://ui.shadcn.com/docs)
- 防止 AI slop 的产品规则：每个面板、标签、图标、动效都须服务当前任务；不用装饰性 KPI、重复卡片、无意义渐变、虚构活动或一屏多个同权重主操作填空。允许 Kimi 有意设计品牌特征，不把任何一种“默认 SaaS 模板”当答案。

## 2. 令牌与复用契约

下列是**角色，不是新配色方案**。Kimi 必须提供“角色 → 数值／字族 → 使用位置 → 各状态”的单一映射，Root 据此实现；未定项标记待定，不能临场另选审美。组件只消费令牌／批准的 variant，例外必须说明任务理由。

| 类别 | 必须命名的角色 | 使用约束 |
| --- | --- | --- |
| 颜色 | 页面、正文、次级正文、卡片、浮层、主操作、次操作、交互高亮、边界、输入、焦点 | 背景／前景成对；映射 shadcn 的 background、foreground、card、popover、primary、secondary、muted、accent、border、input、ring；辅助文字也须可读 |
| 状态 | 信息、等待、成功、警告、错误／破坏性操作 | 与品牌装饰分离；每种配文本／图标，不仅靠颜色；“已确认”不等于“机构批准” |
| 字体 | 页面标题、区块标题、正文／会话、字段标签、辅助文字、文档正文、等宽数据 | Kimi 定字体、字号、字重、行高和字距；中英有匹配回退。缩小辅助字不能成为解决布局问题的默认手段 |
| 间距／尺寸 | 页边距、区块距、组内距、控件内距、目录密度、阅读宽度、composer 最大高度 | 同一层级复用同一档；桌面／手机映射明确。断点由内容可用性决定，不只缩小桌面 |
| 圆角／层次 | 控件、容器、浮层；分隔、遮罩、必要阴影 | Kimi 定少量档位，避免每个卡片独立风格；边框和阴影不能代替内容层级 |
| 焦点／动效 | focus-visible、选中、按下、禁用、加载；反馈时长、减少动效模式 | focus 与 selected 不混淆；不得无替代地去掉轮廓，不以动画延迟操作；支持 reduced-motion |

颜色令牌和圆角映射遵循 [shadcn theming](https://ui.shadcn.com/docs/theming)；字号、间距、阅读宽度及业务状态的具体规则是 Nestlet 设计决定，不是 shadcn 或 WCAG 指定的统一数值。

## 3. 三个任务面的层级

1. **聊天是工作入口。** 顶部显示当前客户／案件和真实保存状态；中央是可读会话，输入区是默认主操作。文件／图片是输入区附件能力，保留 chooser，拖放不是唯一入口。“提取事实／核对／生成文档”在相关上下文出现，不能与“发送”并排争抢首要动作。空态提供一句用途及真实下一步，不预填虚构历史。
2. **目录用于找回工作。** 客户搜索 → 客户下案件 → 会话／文档，当前所在位置始终明确。客户同名时用真实案件信息辅助区分；显示名不自动当作法定姓名。桌面可常驻侧栏，手机用有名称的导航入口及可关闭面板；不能把侧栏全部压成一排小图标。记录数、最近时间及保存标记必须来自服务端。用户只能看自己的记录。
3. **文档优先阅读。** 标题、类型、版本、草稿／历史状态、所属案件先于操作；正文是最大视觉主体。编辑、复制、下载放在稳定工具区，危险操作降级。手机改单列阅读，不能把桌面纸张固定宽度缩成微字。缺失必需信息先集中询问，已确认答案复用；来源与修正贴近事实，聊天建议不能自动获得确认。

约束：[客户／案件 API](customer-case-api.md)、[文档契约](document-context.md)、[聊天 API](chat-api.md)。旧版本文档保留为历史；过期 final 的正常下载受阻时解释并引导重新生成，不能静默覆盖。界面中文默认／英文可切换，正式文档保持英文；不偷偷翻译已有事实或编辑内容。

## 4. 组件不能只交付默认态

每个适用组件交付 default、hover、focus-visible、pressed、disabled、busy、invalid、selected/open 状态；不适用项注明理由。状态同时检查视觉、键盘、可访问名称、服务端结果与恢复动作。

| 组件族 | 最小行为与状态 |
| --- | --- |
| Button／图标按钮 | 主、次、低强调、破坏性 variants；图标按钮有明确名称；busy 防重复提交且说明进度，禁用原因可见；无效状态不是“什么都没发生” |
| Field／Input／Textarea／Select | 持续可见标签，帮助与错误关联，必填／可选清楚；placeholder 不代替标签；错误保留已有输入；原生控件优先，组合控件统一封装。[Field](https://ui.shadcn.com/docs/components/field) |
| Dialog／Sheet／菜单 | 弹层有标题、合理初始焦点、关闭／返回焦点；真正 modal 才锁背景与焦点。关闭前若有未保存编辑，走统一保护路径，不吞掉数据 |
| 目录列表／Tab／披露区 | 当前项、展开、加载、空、无搜索结果、失败分别可辨；导航用链接／按钮，不滥用 menu 或 grid 角色；若采用 Tabs，完整实现相应键盘交互 |
| 上传／附件 | 格式和限制可见；待发送、处理中、成功、失败、移除分别明确；处理过的文本与图片不保留的限制如实说明；删除附件不等于删除已保存材料 |
| 会话／文档／状态条 | 等待首个内容、真实流式、完成、中断、失败与历史版本均有样式；保存、复制、生成不能共用含混的“成功”；重要错误不能只在短暂 toast 中出现 |

APG 是实现指导而非独立合规证书：[modal](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/) 要求对应的焦点行为；[tabs](https://www.w3.org/WAI/ARIA/apg/patterns/tabs/) 使用方向键及正确关联。不能只复制 ARIA 属性而不实现操作。[APG 使用说明](https://www.w3.org/WAI/ARIA/apg/practices/read-me-first/)

## 5. 空、慢、错和中断必须能继续

| 场景 | 用户所见与恢复契约 |
| --- | --- |
| 首次空态／搜索无结果 | 区分“还没有客户／文档”和“没有匹配结果”；保留搜索词，提供清除搜索或创建入口，不把服务错误画成空目录 |
| 加载／处理 | 说明正在做什么；未知时长不用假百分比。骨架只代表待加载区域，不伪装成真实记录；保留现有内容和可取消路径 |
| 流式响应 | 只展示真实 delta；区分等待首字、正在生成与完成。用户向上阅读时不强行滚回底部，提供“回到最新”；完成／失败做节制的状态播报，不逐 token 打断读屏 |
| 停止／断流／刷新 | 保留已有部分文字并标为中断，未终结的用户消息显示未回答；不能伪装完成或自动重复付费请求。重试由用户明确触发，处理 busy／重复 turn，避免重复保存 |
| 网络／服务／保存失败 | 清楚说明哪一步失败、内容是否已存、下一步是什么；保留输入。持久会话与临时模式区分，`CHAT_SAVE_FAILED` 不显示已保存；401 重新登录，409 保留本地编辑并处理冲突 |
| 缺信息／格式错误 | 给可操作的字段级原因；多项错误提供可跳转摘要；确认用户补充后继续，不重复问已解决的同一问题；已知可选项不要冒充必填 |
| 替换／删除／切换案件 | 未保存改动受保护；取消回到原上下文。删除案件明确同时删除会话／文档；迟到响应不得写进新案件或新账户 |

以上是 Nestlet 产品契约。字段错误和摘要参考 [GOV.UK error summary](https://design-system.service.gov.uk/components/error-summary/)；渐进披露、保存后继续与平实说明参考 [USWDS progress easily](https://designsystem.digital.gov/patterns/complete-a-complex-form/progress-easily/)。不引入其品牌，也不暗示政府背书。

## 6. WCAG 2.2 AA 底线与产品建议分开

目标是 [WCAG 2.2 AA](https://www.w3.org/TR/WCAG22/)；下列为相关成功准则的摘要，原文及例外为准。Understanding／APG 是说明材料。**这是筛选出的验收项，不能据此宣称完整页面／完整流程已合规。**

| 正式要求 | 验收重点 |
| --- | --- |
| [1.4.3 对比度](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)、[1.4.11 非文字对比](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html) | 普通文本至少 4.5:1，大文本 3:1；必要控件／状态视觉信息与相邻颜色至少 3:1，分别适用准则例外。用计算样式测量，不从截图猜测；状态不只依赖颜色 |
| [1.4.10 重排](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html)、[1.4.4 放大](https://www.w3.org/WAI/WCAG22/Understanding/resize-text.html) | 竖向阅读在 320 CSS px 等效宽度不丢功能／内容、不需双向滚动，必要二维内容有例外；另测文字放大 200%。390px 截图不能代替这些检查 |
| [1.4.12 文字间距](https://www.w3.org/WAI/WCAG22/Understanding/text-spacing.html) | 用户将适用的行高设至 1.5 倍、段距 2 倍、字距 0.12em、词距 0.16em 时不丢内容／功能；这是承受用户覆盖的能力，不是默认排版必须长这样 |
| [2.1.1 键盘](https://www.w3.org/WAI/WCAG22/Understanding/keyboard.html)、[2.4.7 可见焦点](https://www.w3.org/WAI/WCAG22/Understanding/focus-visible.html)、[2.4.11 焦点不被遮挡](https://www.w3.org/WAI/WCAG22/Understanding/focus-not-obscured-minimum.html) | 核心任务可键盘操作；焦点可见且不被作者创建的内容完全遮住。AA 的“不完全遮挡”不要误写成“任何遮挡都违规” |
| [2.5.8 最小目标](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html) | 目标至少 24×24 CSS px，或符合间距／等效／行内等例外；测实际可点击区域而非图标大小 |
| [3.3.1 错误识别](https://www.w3.org/TR/WCAG22/#error-identification)、[3.3.2 标签](https://www.w3.org/TR/WCAG22/#labels-or-instructions)、[4.1.3 状态消息](https://www.w3.org/WAI/WCAG22/Understanding/status-messages.html) | 自动发现的输入错误用文字说明；字段有标签／说明；适用状态能以程序方式获知，无需每次移走焦点 |

其他适用 A／AA 条款仍须在完整验收中检查，包括语义结构、名称／角色／值、语言、焦点顺序、颜色使用、无键盘陷阱、拖动替代及可访问登录。中文页面内英文文档标注正确语言。

**额外产品目标，不混称 AA 统一要求：**高频手机按钮优先做到至少 44×44 CSS px；输入区、错误和主操作保持充分可见；正文行宽／行高由 Kimi 试读决定；减少动效。44×44 与 WCAG 2.5.5 的 AAA 增强目标相关，但本项目单独采用它不代表达到 AAA。

- [ ] 桌面完成 Tab／Shift+Tab／Enter／Space 及组件所需方向键路径；覆盖目录、文件选择、发送／停止、错误恢复、弹层关闭、文档操作和登录；长输入中文 IME 组合期间不能误发
- [ ] 在支持的真实手机／浏览器打开软键盘：聚焦输入、增长多行、滚动旧消息、关闭键盘、旋转屏幕；composer、当前字段及关键动作可达，焦点不跳到页面外。视口模拟不能充当软键盘证据
