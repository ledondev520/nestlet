# 体验报告迭代

## 基线与范围

2026-10-09：从 GitHub 最新 `main` 的 `66725b9d98ecc50b4dadc3f2b224f312943403e8` 建立独立分支。需求来自产品所有者提供的 10 月 8 日体验报告：以最新版本核实并改善具体使用摩擦。生产 `/api/health` 可用，但健康响应不含部署 SHA，不能据此宣称线上代码与本基线一致。

用户旅程：打开已有案例 → 关联客户或改名 → 核对已存事实 → 找到官方表格及填写参考 → 返回同一案例继续工作；不需要的案例可经明确确认删除。保持现有视觉体系、人工确认、账号隔离和版本冲突保护。

修改范围：React 案例管理、核对/参考展示、聊天拒绝反馈、加载和上传控件，以及对应测试。复用已有 API；不修改数据库结构、模型/供应商/部署配置，不处理生产账号的数据。

## 报告问题对照

| 问题 | 本轮处理与边界 |
| --- | --- |
| N-01 删除入口 | 新增案例删除及二次确认。删除本案例、所属对话/文书与当前工作区未保存输入；原件、下载副本和备份保留。未新增单条消息、客户或原件删除，也不自动清理测试数据。 |
| N-02 客户关联 | 已存事项可关联、解除关联；客户详情可选择已有事项。保存后同步刷新案例与客户详情。使用当前案例版本，保留事实、出处、文书上下文与问题记录。 |
| N-03 官方表格 | 文档页提供官方来源、逐步准备说明和已核对事实/出处对照。不是官方字段映射认证，不填写或替代官方表格；不生成未经核实的提交包或截止日期。 |
| N-04 敏感信息 | HTTP 流开始前的明确敏感信息拒绝恢复输入并移除临时气泡，不再触发错误的历史对账或保存不确定提示。流开始后的错误仍保留原有恢复语义。 |
| N-05 核对结果 | 材料页/文档页逐项显示已核对、未填写、待核对、冲突。文档页区分必填缺项和生成时省略的可选项。“辅助文书可生成”不代表官方提交材料齐备，不把未分配的案例编号强行设为必填。 |
| N-06 confirm | 最新基线已支持唯一可见确认卡的直接人工 confirm/确认及按钮保存；保持并回归既有流程，不重复实现。 |
| N-07 参考机构 | 已存机构可识别且与选择器不一致时，折叠参考区之外显示警告；用户可显式匹配参考机构，不更改事实或确认状态。 |
| N-08 语言 | 上传入口改为自定义双语按钮，文件队列显示实际文件名。已有用户内容和文件名不自动翻译。 |
| N-09 加载/统计 | 已有案例加载时不显示“尚未保存”；关联/删除刷新目录与客户详情。现有侧栏使用成功写入的数据修订通知刷新。 |
| N-10 客户字段 | 保持轻量客户标签，并明确仅用于整理，不作为法律名称或收件人。未扩展电话/邮箱等 CRM 字段。 |
| N-11 等待 | 最新基线已有流式展示、处理中状态与停止按钮；保留并回归验证。 |
| N-12 历史引用 | 网页链接已有安全 Markdown 展示；历史保存记录引用只在实际出现引用编号时解释其版本局限，并指向“搜索记录”核对当前资料，不伪装为重新验证的来源。 |
| N-13 未命名案例 | 案例管理提供明确改名/删除；保留已有会话自动命名，不自动删除空案例。 |
| N-14 长文本 | 常显 8,000 字符上限计数；原报告的粘贴禁用现象仍无稳定复现，不宣称修复未复现故障。 |
| N-15 登录失效 | 最新基线已有持久会话与恢复机制。无该偶发现象的稳定复现，不修改会话策略。 |

## 验收

- 新建入口的失败测试先运行：敏感信息拒绝不应增加历史读取；已有案例必须可打开管理表单。两项先失败，修改后通过。
- 真实 DOM 验证保存保留内容与版本、冲突后停止重试、删除二次确认和同步重复点击锁。
- 真实浏览器/HTTP/SQLite，合成数据，覆盖桌面 1440px 与手机 390px：关联/解除/从客户重新关联、改名、未核对/未填项、官方来源、机构错配且事实不变、取消删除、确认后级联范围、原件可下载与当前工作区重置。
- 运行构建、语法、前端、后端及受影响浏览器回归。具体结果见 `docs/validation.md`，区别本机字体限制与 Linux CI；不宣称真实模型、生产部署或真实业务合规验收。

## 回滚

界面与流程修改可回退代码，无数据库迁移。用户已执行的删除无法通过代码回滚撤销；确认文案明确范围，原件仍保留。不要把数据库备份恢复当作普通界面撤销。
